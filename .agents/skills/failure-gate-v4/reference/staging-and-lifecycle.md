# Staged controls, policy applicability and retained lifecycle

Normative for authoring, staging, activation and recovery. Read the actual current
approved task/policy and canonical Port Authority contract/consumers first.
Definitions, draft tasks and passing fixtures are not host authority. Use only
canonical `.agents` sources; preservation ZIPs and disposable mirrors are not
implementation sources. Keep deliverables outside `.local/`.

## 1. Discover governance before selecting a validation route

Record the authoritative evidence, scope and revision for governance status:

| Verified policy status | Required route |
|---|---|
| ACTIVE | Required-tier runs use the verified task-ID/approved-plan checked route. Diagnostics/comparisons need their separate registered bounded capability. Existing gates remain in force until approved cutover. |
| INACTIVE | Use the verified existing host policy, its actual approval/budget sources and equivalent finite supervisor. Do not demand imaginary Failure Gate APIs or self-register another policy. |
| UNKNOWN | Block dependent dispatch/activation/acceptance. Missing files, an unavailable endpoint or a draft task do not prove inactivity or approval. Continue only unrelated work with independently established permission. |

Apply this decision locally in every parallel instruction, checklist and example.
The ordinary task/tier, allocator, activation, monitor and completion requirements
in this package govern ACTIVE Failure Gate routes and separately approved
installation of those routes; they are not mandatory imaginary services on an
INACTIVE host. All finite validation still follows
[validation-budgets.md](validation-budgets.md). Explicit checked requests always
fail closed on invalid/missing bindings, even if general governance is INACTIVE;
never downgrade such a request to an independent command. Genuine independent
callers keep their existing invocations/authority; Agent labels do not create it.
Checked runtime reclaim remains a distinct required capability in every policy
state; INACTIVE general validation never exempts reclaim approval or attestation.

## 2. Staging and genuine activation are separate

Record each control/caller, source revision/hash, actual current approval/bindings,
fixture result, host evidence and dependencies independently:

| State | Required proof | Limits |
|---|---|---|
| STAGED | Applicable staging permission; canonical integrity/frontmatter/references verified; inert placement | No live wiring, execution permission, host acceptance, validation PASS or completed installation. Failed integrity cannot satisfy STAGED. |
| NON_RECLAIM_VERIFIED | Named real callers passed authorized admission, finite budgets, conflict coverage and applicable host acceptance twice consecutively | No reclaim or development exception implied; unrelated callers remain unverified. |
| LIVE_RECLAIM_ENABLED | Real independent attestation, exact checked claim/rechecks/outcome acknowledgement and authorized caller acceptance twice consecutively | No blanket future grant, production bypass, unrelated targets or automatic validation PASS. |

Isolated checks have a separate PASSED/FAILED/BLOCKED/NOT_RUN value. STAGED with
checks BLOCKED remains unverified. Missing applicable proof is BLOCKED, not “not
applicable.” Run permitted bounded bundle suites twice; fixtures never substitute
for two real authorized host acceptance runs on a control being enabled.

Missing reclaim capability alone does not block authorized inert staging,
read-only discovery or separately permitted isolated fixtures. But a current
approved task that gates every edit/test on authority remains blocked until an
authorized staged-task revision. Do not reinterpret that task, manufacture approval
or refresh its revision merely from this skill update. Revalidate actual running
work and approval bindings before any authorized cutover.

Stage separately if a same-path copy would overwrite an active script. Do not
change package/workflow hooks, callers, services or actual lock state while staging.
Unsafe legacy wiring remains an unresolved risk, not repaired by file placement.
Use separately approved scoped remediation/cutover; failed activation cannot
enable the new control. Restore only authorized safe prior wiring; unsafe or
uncertain rollback stays blocked, not a claimed working baseline.

Before non-reclaim activation inspect the whole transitive graph: pre/post hooks,
aliases, nested runners and startup cleanup. An implicit reclaim dependency
requires real reclaim capability. Do not remove that safety dependency just to
pass. Production-marked admission needing a development exception still requires
real attestation. Fixture adapters and removed real production flags prove neither
admission nor activation. Fixtures/adapters exist only in private simulations.
Stage labels waive no required-tier evidence, repairs, coverage or completion gate.

## 3. Mandatory v2 recovery disposition and authoritative exclusion

Port Authority leases require boolean `recoveryRequired`. It is true from
reservation BEFORE dispatch through supervision/transition errors, owner crashes
and uncertain cleanup.
Only a healthy verified completion/release transaction writes false. Mutating
transition failures retain sidecars; successful read-only rejection does not
invent one. A local field is lifecycle evidence, never authenticated approval.
Healthy release describes the verified supervision transaction, not a passing
child: ordinary nonzero child outcomes remain raw failures and never become PASS
merely because safely supervised release finalized the lease.

Ordinary dead-owner recovery requires a compatible finalized lease:
`phase:"finished", recoveryRequired:false`, verified owner death and no surviving
or unknown group/observed work. Authoritative unresolved claims/evidence may still
block a host caller even when that local lease is eligible. True/unfinalized/
incompatible leases remain blocked after known local work stops. Older v2 leases
missing the field are incompatible: never add false or silently migrate them.
Heartbeat/max-hold age, raw zero, parent death, no sidecar, manifest/reference or
Agent narrative authorizes no unlink, replacement, retry or revision refresh.

Discover the real separately approved bounded recovery capability; no function
name here is an endpoint. Bind task/approved plan/run/stable operation, verified
workspace/root/current boot/attestation applicability, exact canonical lease
path/token and owner/watchdog/owned process incarnations, preserved incident/raw
evidence, current policy/approval and finite inherited budgets. Reconcile or stop
conflicting callers/contenders through authorized routes before release.
Resolve unknown claim/write/intent effects by the stable operation identity and
authoritative readback, not another claim, repeated signal or blind write retry.
Known local quiescence alone cannot clear authoritative exclusion.
Only actual host policy and checked durable recovery acknowledgement may resolve
retained errors and permit new work. Missing transport, uncertain contenders,
discovery gaps, surviving work, lost acknowledgement or exhausted budget retains
BLOCKED and exclusion. Preserve incidents/raw outcomes after successful recovery;
recovery does not convert the prior run to PASS or grant a tier/coverage waiver.

## 4. Independent gate and whole-tree supervision

The current local template journals a private IPC startup gate identity and
registers it with an independently running watchdog BEFORE user dispatch. The
watchdog has its own session; registration/handshakes are bounded at two seconds.
It watches exact owner incarnation, owned group/observed descendants and the
remaining monotonic execution deadline, with bounded TERM/KILL verification.
Private worker modes require IPC. No registration/failed handshake means no user
dispatch. Watchdog loss blocks healthy release and triggers bounded known-owned
cleanup; error/exclusion evidence stays retained. The watchdog cannot approve
reclaim, delete leases, manufacture PASS or replace checked task single-flight.

Real host callers must prove the startup order, owner stall AND owner death,
original-group timeout survival, watchdog failure detection, exact whole-tree
cleanup and no known owned survivors. A hung child with a responsive owner does
not test owner stall. Admission expiry after authorized launch preserves owned
supervision, not new launch authority or new unrelated/expired reclaim signals.
Newly observed owned descendants receive the current permitted termination signal;
reclaim batches separately obey checked intent/replay rules.
Discovery/termination uncertainty retains authoritative exclusion even if known
local work stopped. Exit, stream close, signal delivery and shell/client timeout
are distinct observations, none alone establishes quiescence.

Linux `/proc` polling is cooperative: no pidfd/cgroup, hostile-code,
uninterruptible-I/O or remote-job guarantee. If daemonization/double-fork/instant
escape or untracked remote work cannot be ruled out, require a verified host
job/cgroup/provider boundary or block acceptance. GNU timeout alone does not own
detached sessions. Local guard numbers are not registry-approved budgets.
Bound reads, registration, execution, cancellation, capture and parent/attempt
time across nesting/reentry/retries/recovery under the applicable verified policy.

## 5. Untrusted input shapes and structured outcomes

Validate envelopes before field access and every process member before identity
use. Reject null, primitives, arrays, invalid/duplicate PID/start-time targets and
invalid task/plan/run/scope bindings. Bound no-follow nonblocking regular-file JSON
reads before dispatch; outer oversight still covers kernel/I/O stalls.
Malformed members yield structured INVALID (2); unsupported discovery/envelope/
ownership yields structured UNKNOWN (4), as the current consumer defines.
Both are non-success with no signal intent/delivery. An uncaught TypeError or
bare exit 1 is a broken input boundary, not an attempted-cleanup outcome, claim,
successful recovery or acceptable evidence. Preserve raw operation/child results,
claims, intents, actual deliveries, partial errors, termination/port checks and
acknowledgement separately from assessment. Cleanup never replaces tier evidence.

## 6. Verification and preservation

Use `tests/test_staging_lifecycle.py` for labelled policy simulations and the
canonical PA bounded adversarial fixtures for executable local consumer evidence.
Neither proves real protected provider or deployed activation. Required cases:
ACTIVE/INACTIVE/UNKNOWN routes including invalid explicit checked requests; task-wide
staging gates; implicit reclaim; two real caller runs versus fixtures; true/
unfinalized/missing recovery disposition; quiescent retained errors without sidecars;
exact separately approved recovery and unknown commit reconciliation; registration
before dispatch, owner stall/death, watchdog loss; malformed envelopes/members with
structured zero-signal denial. Recheck healthy/nonzero exits, reentry, serialization,
cancellation, legitimate finalized-quiescent recovery and production guards.
Preserve exact protocol v1 and all existing failure/provenance/coverage/ownership,
actor-optional ordinary tier events, independent callers and owner closure rules.
Report fixture and host outcomes separately with concrete blockers; paired
confirmation reads the complete canonical text/references and corrects only this
skill scope, never an application feature or approval service.
